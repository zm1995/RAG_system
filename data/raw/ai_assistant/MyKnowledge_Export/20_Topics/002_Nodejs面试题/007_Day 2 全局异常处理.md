## ✅ 一句话粗暴定义

* **`unhandledRejection`**：**"Promise 被拒绝（rejected）了，但没人管（没有 `.catch()`）"** → 触发这个事件。
* **`uncaughtException`**：**"同步代码或异步回调里抛出了错误，但没有任何 `try-catch` 接着"** → 触发这个事件。

 > 
 > **记住：一个是"Promise 没人接盘"，一个是"异常没人接住"；前者是'异步债'，后者是'同步雷'。**

---

## 📊 两者对比表（面试直接背）

|维度|**unhandledRejection**|**uncaughtException**|
|--|------------------|-----------------|
|**触发场景**|Promise 被 reject，但没有 `.catch()` 或 `try-catch`|同步代码或异步回调中抛出错误，没被捕获|
|**错误来源**|异步（Promise / async 函数）|同步 + 异步回调（如 `setTimeout`、事件监听）|
|**默认行为**|打印警告，**不退出进程**（Node v15+ 会触发警告，但不退出）|**进程立即退出**（防止状态不一致）|
|**是否可以恢复**|可以（记录日志后继续运行）|**不建议**（进程状态可能已损坏）|
|**最佳实践**|记录错误日志 + 发送告警|记录日志 + **优雅退出** + 重启进程（PM2）|

## 🔬 深入理解：unhandledRejection

### 1. 什么情况会触发？

````javascript
// ❌ 情况1：Promise 被 reject，但没有 .catch()
Promise.reject('出错了');
// 触发 unhandledRejection

// ❌ 情况2：async 函数内部抛出异常，但调用方没捕获
async function badAsync() {
  throw new Error('async 错误');
}
badAsync();  // 没有 await，也没有 .catch()
// 触发 unhandledRejection

// ❌ 情况3：.then() 中抛出错误，但链尾没有 .catch()
Promise.resolve()
  .then(() => { throw new Error('then 错误'); });
// 触发 unhandledRejection
````

### 2. 如何监听并处理？

````javascript
process.on('unhandledRejection', (reason, promise) => {
  console.error('❌ 未处理的 Promise 拒绝:');
  console.error('原因:', reason);
  console.error('Promise:', promise);
  
  // 最佳实践：
  // 1. 记录错误日志（写入文件 / 发送到监控平台）
  // 2. 发送告警（钉钉、邮件、Slack）
  // 3. 不退出进程（因为 Promise 是隔离的，状态不会污染全局）
});
````

### 3. 如何避免误报？（主动捕获）

````javascript
// ✅ 正确写法：使用 .catch()
Promise.reject('出错了')
  .catch(err => console.error('捕获到:', err));

// ✅ 正确写法：使用 try-catch
async function goodAsync() {
  try {
    await badAsync();
  } catch (err) {
    console.error('捕获到:', err);
  }
}

// ✅ 正确写法：在顶层使用 .catch()
badAsync().catch(err => console.error('顶层捕获:', err));
````

## 🔬 深入理解：uncaughtException

### 1. 什么情况会触发？

````javascript
// ❌ 情况1：同步代码抛出错误
throw new Error('同步错误');
// 触发 uncaughtException，进程退出

// ❌ 情况2：异步回调中抛出错误（无法被外部 try-catch 捕获）
setTimeout(() => {
  throw new Error('setTimeout 错误');
}, 100);
// 触发 uncaughtException，进程退出

// ❌ 情况3：事件监听器中抛出错误
const EventEmitter = require('events');
const emitter = new EventEmitter();
emitter.on('event', () => {
  throw new Error('事件监听错误');
});
emitter.emit('event');
// 触发 uncaughtException，进程退出
````

### 2. 如何监听并处理？

````javascript
process.on('uncaughtException', (err) => {
  console.error('❌ 未捕获的异常:');
  console.error('错误:', err);
  console.error('堆栈:', err.stack);
  
  // 最佳实践：
  // 1. 记录错误日志
  // 2. 发送告警
  // 3. 优雅退出（释放资源：关闭数据库连接、文件流等）
  // 4. 退出进程（让进程管理器 PM2 重启）
  process.exit(1);  // 必须退出，否则进程状态可能已损坏
});
````

### 3. 为什么不能继续运行？

````javascript
// 错误示例：在 uncaughtException 中继续运行
process.on('uncaughtException', (err) => {
  console.error('捕获异常，继续运行...');
  // 危险！此时进程状态可能已损坏
});

// 可能导致的后果：
// - 内存泄漏
// - 数据库连接状态不一致
// - 请求处理出现诡异行为
// - 安全漏洞（因为某些状态未被正确清理）
````

**官方文档原话**：

 > 
 > "An uncaught exception is a very serious error that indicates that the process is in an inconsistent state and cannot continue safely."

## 🎯 实战最佳实践（面试必答）

### 方案1：基础版（小项目）

````javascript
// 在入口文件顶部添加
process.on('unhandledRejection', (reason) => {
  console.error('未处理的 Promise 拒绝:', reason);
  // 记录日志，但不退出
});

process.on('uncaughtException', (err) => {
  console.error('未捕获的异常:', err);
  // 记录日志
  // 优雅退出
  console.error('进程将退出...');
  process.exit(1);
});
````

### 方案2：专业版（大型项目）

````javascript
const logger = require('./logger');  // 日志模块
const metrics = require('./metrics'); // 监控模块

process.on('unhandledRejection', (reason, promise) => {
  // 1. 记录详细日志
  logger.error('Unhandled Rejection', {
    reason: reason.stack || reason,
    promise: promise
  });
  
  // 2. 发送告警（钉钉/邮件/监控平台）
  metrics.increment('unhandled_rejection');
  
  // 3. 不退出（Promise 是隔离的）
});

process.on('uncaughtException', (err) => {
  // 1. 记录详细日志
  logger.error('Uncaught Exception', {
    error: err.message,
    stack: err.stack
  });
  
  // 2. 发送告警
  metrics.increment('uncaught_exception');
  
  // 3. 关闭资源（数据库、文件流、定时器）
  closeAllResources(() => {
    // 4. 退出进程（让 PM2 重启）
    process.exit(1);
  });
});

function closeAllResources(callback) {
  // 关闭数据库连接
  // 关闭 HTTP 服务器（停止接收新请求）
  // 等待现有请求处理完
  callback();
}
````

## 🎯 面试致命追问（附标准答案）

**问：** "`unhandledRejection` 和 `uncaughtException` 有什么区别？"  
**答：** "`unhandledRejection` 针对 Promise 被拒绝但没有 `.catch()` 的场景，Node v15+ 默认不退出进程。`uncaughtException` 针对同步代码或异步回调中抛出的异常，进程会立即退出。"

**问：** "`uncaughtException` 中为什么必须 `process.exit(1)`？"  
**答：** "因为进程状态可能已损坏（如内存泄漏、数据库连接失效、请求状态不一致），继续运行会导致不可预知的错误。正确的做法是记录日志、释放资源，然后退出，由进程管理器（PM2）重启。"

**问：** "如何避免 `unhandledRejection`？"  
**答：** "在所有 Promise 链末尾添加 `.catch()`，在 async 函数调用时使用 `try-catch`，或者在顶层使用 `.catch()`。同时可以监听 `unhandledRejection` 事件作为最后的兜底。"

**问：** "`uncaughtException` 和 `unhandledRejection` 哪个更严重？"  
**答：** "**`uncaughtException` 更严重。** 因为它意味着进程状态可能已损坏，必须退出。`unhandledRejection` 通常不会污染全局状态，可以记录日志后继续运行。"
