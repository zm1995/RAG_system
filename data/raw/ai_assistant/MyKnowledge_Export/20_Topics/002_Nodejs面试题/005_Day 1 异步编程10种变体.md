## 第一部分：理论基础（30分钟）

### Node 事件循环的6个阶段（按顺序循环）

````
┌───────────────────────────┐
│      ┌─────────────────────┐
│  ┌───┤  1. timers          │  ← setTimeout / setInterval
│  │   ├─────────────────────┤
│  │   │  2. pending callbacks│  ← 系统操作（如TCP错误）回调
│  │   ├─────────────────────┤
│  │   │  3. idle, prepare   │  ← 内部使用，忽略
│  │   ├─────────────────────┤
│  │   │  4. poll            │  ← I/O回调（文件读取等）
│  │   ├─────────────────────┤
│  │   │  5. check           │  ← setImmediate
│  │   ├─────────────────────┤
│  │   │  6. close callbacks │  ← socket.on('close')
│  └───┴─────────────────────┘
│  循环回到 timers
└───────────────────────────┘
````

### 每个阶段之间（关键！）

 > 
 > **在每个阶段结束后，会依次执行：**
 > 
 > 1. **`process.nextTick()` 队列**（最高优先级）
 > 1. **微任务队列**（`Promise.then` / `queueMicrotask`）
 > 1. **然后才进入下一个阶段**

### 实验1：基础四件套（你已经会了）

````javascript
// 实验1
setTimeout(() => console.log('A'), 0);
setImmediate(() => console.log('B'));
process.nextTick(() => console.log('C'));
console.log('D');
````

**预期输出**：`D → C → A → B`（或 `D → C → B → A`，取决于启动时机）

**关键结论**：`nextTick` > 微任务 > 宏任务（`setTimeout` 和 `setImmediate` 顺序不固定）

### 实验2：setTimeout 嵌套 setImmediate

````javascript
// 实验2
setTimeout(() => {
  console.log('A');
  setImmediate(() => console.log('B'));
}, 0);
setImmediate(() => console.log('C'));
````

**预期输出**：`A → C → B`（或 `C → A → B`，取决于第一轮timers阶段）

**解析**：

* 第一轮循环：`setTimeout` 在 timers 阶段执行，输出 `A`，并注册 `setImmediate(B)` 到 check 队列
* 同一轮循环的 check 阶段：执行已注册的 `setImmediate(C)`，输出 `C`
* 下一轮循环的 check 阶段：执行 `setImmediate(B)`，输出 `B`

### 实验5：宏任务内部的 nextTick 和微任务

````javascript
// 实验5
setTimeout(() => {
  console.log('A');
  process.nextTick(() => console.log('B'));
  Promise.resolve().then(() => console.log('C'));
}, 0);
console.log('D');
````

**预期输出**：`D → A → B → C`

**解析**：

1. 同步代码：输出 `D`
1. timers 阶段：执行 `setTimeout` 回调，输出 `A`
1. 当前阶段结束：先清空 `nextTick` 队列 → 输出 `B`
1. 清空微任务队列 → 输出 `C`

**解析**：`nextTick` 队列全部先执行（按注册顺序），然后微任务队列全部执行。

### 实验7：setTimeout 延迟 0 和 1ms 的区别

````javascript
// 实验7
setTimeout(() => console.log('A'), 0);
setTimeout(() => console.log('B'), 1);
console.log('C');
````

**预期输出**：`C → A → B`（几乎总是）

**解析**：`setTimeout(fn, 0)` 在 Node 中会被强制转为 1ms，但 `setTimeout(fn, 1)` 延迟略长，通常排在后面。

### 实验8：setTimeout 和 setImmediate 的"非确定性"

````javascript
// 实验8（跑5次，看结果是否一致）
setTimeout(() => console.log('A'), 0);
setImmediate(() => console.log('B'));
````

**预期输出**：`A → B` 或 `B → A`（**不固定！**）

**原因**：

* 如果事件循环启动时，**timers 阶段**已经过了 1ms，`setTimeout` 回调就绪，先输出 `A`
* 如果事件循环启动时，**timers 阶段**还没到 1ms，先进入 check 阶段，输出 `B`

**面试金句**：**"`setTimeout(fn, 0)` 和 `setImmediate` 的执行顺序是非确定性的，取决于事件循环启动时的计时器状态。"**

### 实验9：fs.readFile 中的 setTimeout 和 setImmediate

````javascript
// 实验9（需要引入fs）
const fs = require('fs');
fs.readFile(__filename, () => {
  setTimeout(() => console.log('A'), 0);
  setImmediate(() => console.log('B'));
});
````

**预期输出**：`B → A`（**固定！**）

**原因**：`fs.readFile` 回调在 **poll 阶段**执行，执行完后直接进入 **check 阶段**，所以 `setImmediate` 先执行，下一轮循环才到 timers 阶段执行 `setTimeout`。

* check 阶段：`G`

## 第一部分：三种异步形态对比（30 分钟）

|形态|写法|优点|缺点|
|--|--|--|--|
|**回调（Callback）**|`fs.readFile(file, (err, data) => {})`|简单、直接|**回调地狱**、错误处理重复|
|**Promise**|`fs.promises.readFile(file).then(data => {}).catch(err => {})`|链式调用、统一错误处理|代码仍有嵌套感|
|**async/await**|`const data = await fs.promises.readFile(file)`|**同步写法、易读**|需要用 `try-catch` 包裹|

### 实验 1：对比三种写法（跑一遍）

````javascript
const fs = require('fs');
const fsPromises = fs.promises;

// ========== 1. 回调写法 ==========
fs.readFile('./test.txt', 'utf8', (err, data) => {
  if (err) {
    console.error('回调错误:', err);
    return;
  }
  console.log('回调数据:', data);
});

// ========== 2. Promise 写法 ==========
fsPromises.readFile('./test.txt', 'utf8')
  .then(data => console.log('Promise 数据:', data))
  .catch(err => console.error('Promise 错误:', err));

// ========== 3. async/await 写法 ==========
async function readFileAsync() {
  try {
    const data = await fsPromises.readFile('./test.txt', 'utf8');
    console.log('async/await 数据:', data);
  } catch (err) {
    console.error('async/await 错误:', err);
  }
}
readFileAsync();
````

**关键结论**：三种写法都能实现异步，但 **async/await 最接近同步代码的可读性**，是 Node 面试和实战的**首选**。

## 第二部分：错误处理（1 小时）—— 面试必考

### 2.1 回调的错误处理

````javascript
// 回调中错误优先（Error-First Callback）
fs.readFile(file, (err, data) => {
  if (err) {
    // 必须处理错误
    console.error(err);
    return;
  }
  // 成功处理 data
});
````

**陷阱**：忘记处理 `err` → 程序继续执行，`data` 为 `undefined` → 后续代码报错。

---

### 2.2 Promise 的错误处理

````javascript
somePromise()
  .then(result => { /* 成功 */ })
  .catch(err => { /* 捕获所有错误 */ });
````

**陷阱**：`catch` 只能捕获**链中之前**的错误，如果 `catch` 后面还有 `then`，`then` 会继续执行。

````javascript
Promise.resolve()
  .then(() => { throw new Error('错误'); })
  .catch(err => { console.log('捕获:', err.message); })
  .then(() => { console.log('我会继续执行'); });
// 输出：捕获: 错误 → 我会继续执行
````

---

### 2.3 async/await 的错误处理

````javascript
async function fetchData() {
  try {
    const data = await someAsyncFn();
    return data;
  } catch (err) {
    console.error('捕获错误:', err);
    throw err;  // 重新抛出，让上层处理
  }
}
````

**陷阱**：**忘记用 `try-catch`** 包裹 `await`，如果异步函数失败，整个程序会抛出未捕获的异常。

````javascript
// ❌ 错误写法
async function badFetch() {
  const data = await someAsyncFn();  // 失败时会抛出未捕获异常
  return data;
}

// ✅ 正确写法
async function goodFetch() {
  try {
    const data = await someAsyncFn();
    return data;
  } catch (err) {
    // 处理错误
    return null;
  }
}
````

## 第三部分：手写 Promise 静态方法（1.5 小时）

### 实验 2：手写 `Promise.all`（面试高频）

````javascript
function myPromiseAll(promises) {
  return new Promise((resolve, reject) => {
    // 1. 参数校验
    if (!Array.isArray(promises)) {
      return reject(new TypeError('参数必须是数组'));
    }

    const results = [];
    let completed = 0;
    const total = promises.length;

    // 2. 空数组直接 resolve
    if (total === 0) {
      return resolve(results);
    }

    // 3. 遍历执行
    for (let i = 0; i < total; i++) {
      // 确保每个元素都是 Promise
      Promise.resolve(promises[i])
        .then(value => {
          results[i] = value;
          completed++;
          if (completed === total) {
            resolve(results);
          }
        })
        .catch(reject);  // 任何一个失败，整体失败
    }
  });
}

// 测试
const p1 = Promise.resolve(1);
const p2 = Promise.resolve(2);
const p3 = Promise.resolve(3);
myPromiseAll([p1, p2, p3]).then(console.log);  // [1, 2, 3]
````

### 实验 3：手写 `Promise.race`（面试常考）

````javascript
function myPromiseRace(promises) {
  return new Promise((resolve, reject) => {
    if (!Array.isArray(promises)) {
      return reject(new TypeError('参数必须是数组'));
    }

    for (const p of promises) {
      Promise.resolve(p).then(resolve).catch(reject);  // 谁先完成就 resolve/reject
    }
  });
}

// 测试
const fast = new Promise(resolve => setTimeout(resolve, 100, '快'));
const slow = new Promise(resolve => setTimeout(resolve, 500, '慢'));
myPromiseRace([fast, slow]).then(console.log);  // '快'
````

### 实验 4：手写 `Promise.retry`（Node 实战高频）

**需求**：网络请求失败时，自动重试 3 次。

````javascript
function myPromiseRetry(fn, retries = 3, delay = 1000) {
  return new Promise((resolve, reject) => {
    const attempt = (count) => {
      fn()
        .then(resolve)  // 成功 → 直接 resolve
        .catch(err => {
          if (count <= 1) {
            reject(err);  // 重试次数用完 → 失败
          } else {
            console.log(`重试中... 剩余 ${count - 1} 次`);
            setTimeout(() => attempt(count - 1), delay);
          }
        });
    };
    attempt(retries);
  });
}

// 测试：模拟一个随机失败的网络请求
const unstableFetch = () => {
  return new Promise((resolve, reject) => {
    Math.random() > 0.5 ? resolve('成功') : reject('失败');
  });
};

myPromiseRetry(unstableFetch, 3, 500)
  .then(console.log)
  .catch(console.error);
````

## 第四部分：并发控制（1 小时）—— 进阶必考

**需求**：有 10 个异步任务，但只能同时执行 3 个（防止服务器压力过大）。

### 实验 5：限制并发数的实现

````javascript
async function concurrentControl(tasks, limit = 3) {
  const results = [];
  const executing = [];

  for (const task of tasks) {
    // 执行任务（确保是 Promise）
    const p = Promise.resolve(task());
    results.push(p);

    // 如果达到并发限制，等待任意一个完成
    if (limit <= tasks.length) {
      const e = p.then(() => {
        // 从执行列表中移除自己
        const index = executing.indexOf(e);
        if (index > -1) executing.splice(index, 1);
      });
      executing.push(e);

      if (executing.length >= limit) {
        await Promise.race(executing);  // 等待最快的完成
      }
    }
  }

  // 等待所有任务完成
  return Promise.all(results);
}

// 测试
const createTask = (id, delay) => {
  return () => new Promise(resolve => {
    console.log(`任务 ${id} 开始`);
    setTimeout(() => {
      console.log(`任务 ${id} 完成`);
      resolve(id);
    }, delay);
  });
};

const tasks = [
  createTask(1, 1000),
  createTask(2, 500),
  createTask(3, 2000),
  createTask(4, 1500),
  createTask(5, 800),
];

concurrentControl(tasks, 2);  // 最多同时执行 2 个
````
