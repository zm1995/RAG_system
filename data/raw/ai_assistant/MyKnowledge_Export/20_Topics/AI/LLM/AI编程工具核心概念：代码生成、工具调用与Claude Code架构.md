## 第一部分：推理反思模型

### 什么是推理反思模式

推理反思模式要求大模型在输出最终答案前，先进行内部推理和自我检查，而不是直接生成结果。

### 提示词模板

````text
你是一个编程专家，需要遵循"推理 → 反思 → 生成"的流程来回答代码相关的问题。

**步骤1：推理**
- 先理解用户的问题，分析需求、边界条件、输入输出。
- 列出关键逻辑步骤、可能的算法或数据结构。
- 指出潜在的技术难点或容易出错的地方。

**步骤2：反思**
- 检查上面推理是否有逻辑漏洞或遗漏需求。
- 考虑是否有更简洁、性能更好或更可读的实现方式。
- 确认代码风格、错误处理、边界条件是否周全。
- 如果发现问题，修正推理结果。

**步骤3：生成**
- 输出最终代码，并在代码中使用清晰注释。
- 如果代码较长，可以分块说明，但最终必须给出完整可运行的代码块。
- 最后简要说明：为什么这种实现方式优于其他常见做法（如果适用）。

**输出格式示例：**
[推理]
...

[反思]
...

[生成]
```代码语言
...代码...
````

````

## 第二部分：代码生成 vs 工具调用

### 核心结论

> **生成是AI的软件能力，执行是AI的硬件能力。后者需要通过"工具"来赋予。**

### 大模型自己能做的事

| 能力 | 说明 |
|------|------|
| 生成代码文本 | 如 `def hello(): print("hi")` |
| 生成命令行文本 | 如 `ls -la` |
| 生成配置文件、正则表达式等 | 任何纯文本内容 |

**你的角色**：复制粘贴，手动执行。

### 需要你写工具才能做的事

| 能力 | 说明 |
|------|------|
| 真正在服务器上执行命令 | 需要 `execute_command` 工具 |
| 真正创建/编辑文件 | 需要 `write_file` / `edit_file` 工具 |
| 真正安装软件包 | 需要 `run_pip_install` 等工具 |
| 查询数据库、调用API等 | 需要对应的网络工具 |

### 一个类比：聪明的管家

| 角色 | 比喻 | 行为 |
|------|------|------|
| 大模型 | 聪明但手脚被束缚的管家 | 能思考、规划、写方案 |
| 你写的工具 | 管家可以使用的工具/指令 | 封装真实的、有副作用的行为 |
| 用户 | 房子的主人 | 下达目标，获得结果 |

## 第三部分：Claude Code泄露源码揭示的真相

### 核心设计哲学

源码注释中明确写道：

> **"agent能做什么，完全由它拥有的工具集决定。系统中没有任何后门让agent绕过工具直接操作环境。"**

### 工具即能力边界

Claude Code内置了约40个工具，每个都是独立的、权限隔离的能力单元：

| 工具名 | 功能 | 实现者 |
|--------|------|--------|
| `BashTool` | 执行Shell命令 | Anthropic工程师 |
| `FileReadTool` | 读取文件 | Anthropic工程师 |
| `FileEditTool` | 编辑文件 | Anthropic工程师 |
| `GrepTool` | 代码搜索 | Anthropic工程师 |
| `AgentTool` | 派生子Agent | Anthropic工程师 |

### 核心执行循环（伪代码）

```typescript
async function agentLoop(messages) {
  while (true) {
    // 1. 调用模型，模型返回要调用哪个工具、传什么参数
    const response = await callModel(messages);
    
    // 2. 如果没有工具调用，结束
    if (!response.toolCalls) return response.text;
    
    // 3. 执行工具（这里调的是你写好的工具函数）
    const toolResults = await executeTools(response.toolCalls);
    
    // 4. 把结果喂回去，继续循环
    messages = [...messages, response, ...toolResults];
  }
}
````

### 责任分工表

|类型|谁负责|具体内容|
|--|---|----|
|写工具函数|你（或框架）|`executeCommand`、`writeFile`等|
|注册工具给模型|你|告诉模型可调用的工具及格式|
|执行工具调用|你（或框架）|解析模型输出，真正执行操作|
|决定调用哪个工具|大模型|输出 `tool_call: BashTool`|
|生成参数内容|大模型|输出具体的命令字符串、文件内容|

### 实际执行示例

**目标**：让AI列出当前目录的文件

1. **你写工具定义**：

````json
{
  "name": "list_files",
  "description": "列出目录中的文件",
  "parameters": { "directory": "string" }
}
````

2. **大模型输出**（不是执行，只是输出文本）：

````json
{
  "tool_call": "list_files",
  "arguments": { "directory": "." }
}
````

3. **你执行**：

````bash
ls -la .
````

## 第四部分：总结

1. **推理反思模式**：让大模型在生成前先推理和检查，提高代码质量。只需给模型合适的提示词模板，不需要额外代码。

1. **代码/命令行生成**：大模型完全可以直接生成这些文本内容，你只需复制粘贴执行。

1. **工具调用**：如果你希望AI能"自动做事"（而非只"写出来"），你需要：
   
   * 自己写工具的**实现**（函数代码）
   * 大模型负责生成**调用参数**和**调度决策**
1. **Claude Code的启示**：51万行代码中，大部分是工具实现、权限控制、上下文管理，真正的"调模型"逻辑很少。这说明构建一个AI Agent的核心工作量在于**写工具**。

## 关键术语速查

|术语|含义|
|--|--|
|推理反思模型|先内部推理、再自我检查、最后生成答案的模式|
|工具 (Tool)|封装真实世界操作的函数，如执行命令、读写文件|
|Function Calling|大模型输出工具调用指令的机制|
|AI Agent|拥有多个工具、能自动决策和执行的大模型系统|
|Claude Code|Anthropic的AI编程助手，其源码泄露揭示了工具调用的核心架构|
