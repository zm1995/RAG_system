## ✅ 一句话粗暴定义

 > 
 > **防抖（Debounce）**：**"等你消停了再执行"** —— 连续触发的事件，只在**最后一次触发后等待指定时间**才执行回调，期间如果再次触发则**重新计时**。

**类比**：坐电梯。人一直进，门就一直不关；没人进了，等几秒门才关上。

---

## 🎯 防抖的4大核心应用场景（面试必答）

|场景|为什么用防抖|典型延迟|
|--|------|----|
|**1. 搜索框输入**|用户每按一个键都发请求，会刷爆服务器；等用户**停止输入**后再搜索|300~500ms|
|**2. 窗口大小改变（resize）**|拖动窗口会触发几十次resize，频繁重绘导致卡顿；等**停止拖动**后再计算布局|200~300ms|
|**3. 滚动事件（scroll）**|滚动时每秒触发上百次，执行复杂逻辑会掉帧；等**停止滚动**后再处理|100~200ms|
|**4. 表单提交按钮**|防止用户**手抖连点**导致重复提交订单|立即执行 + 锁定|

## 💻 防抖的3种实现版本（从简单到完善）

### 版本1：基础版（面试最低要求）

````javascript
function debounce(fn, delay) {
  let timer = null;  // 闭包保存定时器ID
  
  return function(...args) {
    // 每次触发都清除上一个定时器
    clearTimeout(timer);
    
    // 重新设置定时器
    timer = setTimeout(() => {
      fn.apply(this, args);  // 保持 this 和参数正确传递
    }, delay);
  };
}
````

**使用示例**：

````javascript
const search = debounce((keyword) => {
  console.log(`搜索: ${keyword}`);
}, 300);

search('a');  // 触发，但还没执行
search('ab'); // 重新计时
search('abc');// 重新计时
// 等待300ms后，只输出一次 "搜索: abc"
````

### 版本2：立即执行版（带 `immediate` 参数）—— 面试加分项

**需求**：有些场景需要**第一次立即执行**（比如提交按钮），后续防抖。

````javascript
function debounce(fn, delay, immediate = false) {
  let timer = null;
  
  return function(...args) {
    const context = this;
    
    // 如果 timer 为空 且 需要立即执行，立即调用
    const callNow = immediate && !timer;
    
    // 清除上一个定时器
    clearTimeout(timer);
    
    // 设置新定时器
    timer = setTimeout(() => {
      timer = null;  // 重置标志
      if (!immediate) {
        fn.apply(context, args);  // 非立即执行模式下，延迟后执行
      }
    }, delay);
    
    // 立即执行
    if (callNow) {
      fn.apply(context, args);
    }
  };
}
````

**使用示例**：

````javascript
const submit = debounce(() => {
  console.log('提交订单');
}, 500, true);

submit(); // 立即输出 "提交订单"
submit(); // 触发后重新计时，但不执行（防抖）
submit(); // 重新计时
// 500ms后 timer 重置，下一次调用会再次立即执行
````

### 版本3：取消版（带 `.cancel` 方法）—— 面试进阶加分

**需求**：用户离开页面或切换组件时，需要**取消**正在等待的防抖定时器。

````javascript
function debounce(fn, delay, immediate = false) {
  let timer = null;
  
  const debounced = function(...args) {
    const context = this;
    const callNow = immediate && !timer;
    
    clearTimeout(timer);
    timer = setTimeout(() => {
      timer = null;
      if (!immediate) {
        fn.apply(context, args);
      }
    }, delay);
    
    if (callNow) {
      fn.apply(context, args);
    }
  };
  
  // 添加取消方法
  debounced.cancel = function() {
    clearTimeout(timer);
    timer = null;
  };
  
  return debounced;
}
````

**使用示例**：

````javascript
const search = debounce((keyword) => {
  console.log(`搜索: ${keyword}`);
}, 300);

search('abc');
search.cancel();  // 取消本次等待的搜索请求
// 不会输出任何结果
````

## 🔍 防抖 vs 节流（面试必问对比）

|维度|**防抖（Debounce）**|**节流（Throttle）**|
|--|------------|------------|
|**核心行为**|最后一次触发后等待指定时间才执行|固定时间间隔内最多执行一次|
|**类比**|电梯关门（人一直进就不关）|红绿灯（固定时间放行一次）|
|**执行频率**|密集触发时**几乎不执行**，停止后执行一次|密集触发时**固定频率执行**|
|**应用场景**|搜索输入、窗口resize|滚动加载、动画帧、游戏射击|
|**图示**|频率线：`---x-x-x-x-------x`|频率线：`---x---x---x---x---x`|

## 🧪 验证代码（跑一遍，对比防抖和节流）

````javascript
// 防抖
const debouncedLog = debounce((msg) => {
  console.log('防抖:', msg);
}, 1000);

// 节流（参考实现）
function throttle(fn, interval) {
  let lastTime = 0;
  return function(...args) {
    const now = Date.now();
    if (now - lastTime >= interval) {
      lastTime = now;
      fn.apply(this, args);
    }
  };
}

const throttledLog = throttle((msg) => {
  console.log('节流:', msg);
}, 1000);

// 模拟快速触发5次
for (let i = 0; i < 5; i++) {
  debouncedLog(`消息${i}`);  // 只输出最后一次
  throttledLog(`消息${i}`);  // 输出 消息0 和 消息4（间隔1秒）
  // 注意：实际循环极快，节流可能只输出第一次和最后一次
}
````

## 🎯 面试致命追问（附标准答案）

**问：** "防抖中为什么要用 `apply` 或 `call`？不用行不行？"  
**答：** "不行。使用 `apply(this, args)` 是为了**保持原函数的 `this` 指向**和**参数传递**。如果不绑定，回调函数中的 `this` 会丢失（指向全局对象），且无法传递事件参数（如 `event`）。"

**问：** "防抖的 `timer` 为什么要用 `null` 重置？"  
**答：** "为了配合 `immediate` 模式判断 '是否处于等待状态'。如果 `timer` 有值，说明正在等待执行；如果为 `null`，说明不在等待期，可以立即执行。"

**问：** "防抖在 React/Vue 中有什么注意事项？"  
**答：** "组件卸载时需要调用 `.cancel()` 取消未执行的防抖函数，否则可能会在组件卸载后执行 `setState` 导致内存泄漏。"

**问：** "防抖和节流哪个更适合搜索框？"  
**答：** "**防抖**。因为用户期望的搜索结果是'停止输入后的完整关键词'，而非'每个字符都搜索'。防抖可以等到用户停止输入后才发起请求，减少无效请求。"
