## ✅ 一句话粗暴定义

* **引用类型（Reference Types）**：**存在堆内存里，变量存的是"地址/指针"**，拷贝时复制的是地址。
* **基本类型（Primitive Types）**：**存在栈内存里，变量存的是"值本身"**，拷贝时复制的是真实值。

 > 
 > **记住：看"存的是什么"——存地址=引用，存值=基本。**

## 🔬 特殊注意（面试必坑点）

### 1. `typeof null === 'object'` —— 这是JS的**历史遗留Bug**，但`null`是基本类型

````javascript
typeof null  // 'object'  ← 这是错的，但语言规范就这么定的
null instanceof Object  // false  ← 证明它不是对象
````

**面试话术**：`null` 是基本类型，虽然 `typeof` 返回 `'object'`，但它是原始值，没有属性和方法。

---

### 2. `typeof function(){} === 'function'` —— 函数虽然是对象，但`typeof`特殊处理

````javascript
typeof function(){}  // 'function'
function(){} instanceof Object  // true  ← 函数确实是对象
````

**面试话术**：函数是"可调用对象"，`typeof` 单独返回 `'function'`，但它本质是 `Object` 的子类型。

---

### 3. `new String('abc')` 是引用类型，但 `'abc'` 是基本类型

````javascript
const a = 'abc';        // 基本类型
const b = new String('abc');  // 引用类型（String对象）
typeof a  // 'string'
typeof b  // 'object'
a === b   // false（类型不同）
````

**面试话术**：**永远不要用 `new String()` / `new Number()` / `new Boolean()`**，它们会创建包装对象，导致类型混乱。

## 🎯 面试致命追问（附标准答案）

**问：** "基本类型存在栈，引用类型存在堆，对不对？"  
**答：** "**对，但不完全对。** 基本类型确实存在栈里（V8引擎的'小整数'优化可能存寄存器），引用类型的**变量名和地址**在栈，**实际对象**在堆。但闭包中的变量可能逃逸到堆，所以严格说'不绝对'——不过面试这么说就够用了。"

**问：** "`Symbol` 是引用类型吗？"  
**答：** "不是，`Symbol` 是基本类型，每个 `Symbol` 都唯一，但它是不可变的原始值。"

**问：** "`Array` 和 `Function` 是 `Object` 的子类型，那它们有什么区别？"  
**答：** "它们共享 `Object.prototype` 上的方法，但 `Array` 有 `length` 和索引访问特性，`Function` 有 `[[Call]]` 内部方法（可调用）。本质上都是对象，但内部属性和行为不同。"

## 题目一：引用类型传递

````javascript
const obj = { a: 1 };
const arr = [obj];
obj.a = 2;
console.log(arr[0].a);
````

### ✅ 答案：`2`

### 📖 解析（按执行步骤）：

|步骤|代码|内存变化|
|--|--|----|
|1|`const obj = { a: 1 };`|栈内存存 `obj` 指针 → 堆内存存 `{a:1}`|
|2|`const arr = [obj];`|数组第0个元素**拷贝了指针**，指向**同一个**堆内存对象|
|3|`obj.a = 2;`|通过指针修改了堆内存中的值|
|4|`console.log(arr[0].a);`|数组通过同样的指针取值，得到修改后的 `2`|

### 🎯 关键结论：

 > 
 > **引用类型传递的是"指针的拷贝"，不是对象的克隆。** 数组里的对象和原变量指向同一块内存。

## 题目二：事件循环（复习巩固）

````javascript
setTimeout(() => console.log(1), 0);
Promise.resolve().then(() => console.log(2));
console.log(3);
````

### ✅ 答案：`3 → 2 → 1`

### 📖 解析（时间线）：

|顺序|输出|类型|原因|
|--|--|--|--|
|第1轮|`3`|同步代码|直接执行，不进队列|
|第2轮|`2`|微任务（Promise.then）|同步代码执行完，清空微任务队列|
|第3轮|`1`|宏任务（setTimeout）|微任务清空后，才取宏任务执行|

### 🎯 关键结论：

 > 
 > **同步 → 微任务 → 宏任务**（你已经滚瓜烂熟了 ✅）

## 题目三：链式赋值（面试终极杀手题）

````javascript
var a = { n: 1 };
var b = a;
a.x = a = { n: 2 };
console.log(a.x, b.x);
````

### ✅ 答案：`undefined { n: 2 }`（注意：`a.x` 是 `undefined`，`b.x` 是 `{ n: 2 }`）

### 📖 解析（这是最绕的一道，我拆成5步）：

#### 初始状态：

````
栈： a → 堆① { n: 1 }
     b → 堆①（同一个）
````

#### 执行 `a.x = a = { n: 2 };`（关键：赋值运算符是**从右往左**计算，但\*\*`.` 属性访问优先级最高\*\*）

|步骤|执行动作|状态变化|
|--|----|----|
|**Step 1**|先计算 `a.x`（**属性访问优先**）|此时 `a` 指向堆①，所以 `a.x` 就是**堆①的 `x` 属性**（准备赋值，但还没赋）|
|**Step 2**|再计算右边 `a = { n: 2 }`|`a` 变量**被重新赋值**，指向新的堆② `{n:2}`|
|**Step 3**|最后把 `{ n: 2 }` 赋给 **Step 1 中的 `a.x`**（注意：这里的 `a` 用的是 Step 1 中的旧引用，即堆①）|**堆①的 `x` 属性**被赋值为 `{ n: 2 }`|
|**Step 4**|此时 `a` 指向堆②，`b` 指向堆①|堆①变成 `{ n: 1, x: { n: 2 } }`|
|**Step 5**|`console.log(a.x, b.x)`|`a.x` = 堆②没有 `x` 属性 → `undefined`<br>`b.x` = 堆①的 `x` → `{ n: 2 }`|

### 🎨 内存变化图（手绘版）：

````
执行前：
a ───→ 堆① { n: 1 }
b ───→ 堆①

执行 a.x = a = { n: 2 } 后：
a ───→ 堆② { n: 2 }          ← a 指向了新对象
b ───→ 堆① { n: 1, x: 堆② }  ← b 还指着旧对象，但旧对象多了个 x 属性指向堆②

所以：
a.x → 堆② 没有 x → undefined
b.x → 堆① 的 x → { n: 2 }
````

### 🎯 关键结论（面试必背）：

 > 
 > 1. **`.` 属性访问优先级高于赋值**，所以 `a.x` 先被锁定为"堆①的 x 属性"。
 > 1. **赋值运算符从右往左执行**，但左侧的 `a.x` 已经"记住"了旧对象。
 > 1. 结果：**变量 `a` 指向了新对象，但旧对象的 `x` 属性被赋予了新对象**——这叫"剪断绳子但留下了锚点"。
