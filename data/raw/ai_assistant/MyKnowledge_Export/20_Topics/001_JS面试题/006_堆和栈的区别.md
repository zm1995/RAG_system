## ✅ 一句话粗暴定义

* **栈（Stack）**：**"自动分配、自动清理"**，存储**基本类型**和**引用类型的指针**，遵循\*\*后进先出（LIFO）\*\*原则。
* **堆（Heap）**：**"手动分配、自动回收（垃圾回收）"**，存储**引用类型的实际对象**，结构**无序**、空间**大**。

 > 
 > **记住：栈存"名和地址"，堆存"实际东西"；栈小且快，堆大且慢。**

---

## 📊 栈和堆的对比表（面试直接背）

|维度|**栈（Stack）**|**堆（Heap）**|
|--|--------|-------|
|**存储内容**|基本类型值 + 引用类型地址（指针）|引用类型的实际对象|
|**分配方式**|自动分配（编译时确定大小）|动态分配（运行时确定大小）|
|**访问速度**|**快**（直接访问）|**慢**（通过指针间接访问）|
|**空间大小**|小（通常几MB）|大（通常几百MB甚至更大）|
|**生命周期**|函数执行完自动释放（LIFO）|由垃圾回收器（GC）自动回收|
|**内存管理**|系统自动管理|GC 自动管理（但需注意内存泄漏）|
|**典型存储**|`number`、`string`、`boolean`、`null`、`undefined`、`Symbol`、`BigInt`、对象引用地址|`Object`、`Array`、`Function`、`Date`、`RegExp`、`Map`、`Set`|

## 🧠 直观理解：栈和堆的"内存图"

````javascript
// 代码
let name = 'Tom';        // 基本类型 → 栈
let age = 25;            // 基本类型 → 栈
let user = {             // 引用类型
  name: 'Tom',           // 栈：user → 堆地址 0x001
  age: 25                // 堆：{ name: 'Tom', age: 25 }
};
let hobbies = ['coding', 'reading'];  // 栈：hobbies → 堆地址 0x002
````

**内存模型（手绘图）**：

````

│ name: 'Tom' │              │  0x001: {            │

│ age: 25     │              │    age: 25           │
├─────────────┤              │  }                   │
│ user: 0x001 │───────┐      ├─────────────────────┤
├─────────────┤       └─────▶│  0x002: ['coding',  │
│ hobbies:0x002│─────────────▶│   'reading']        │

````

## 🔬 深入理解：栈（Stack）

### 1. 栈的特征（LIFO：Last In First Out）

````javascript
function fn1() {
  let a = 1;        // 入栈
  fn2();            // 调用fn2
  let b = 2;        // 等待fn2执行完才入栈
}

function fn2() {
  let c = 3;        // 入栈（在栈顶）
}
// 执行顺序：fn1入栈 → fn2入栈 → fn2执行完出栈 → fn1继续执行
````

**栈溢出（Stack Overflow）**：递归调用没有终止条件时，函数不断入栈，栈空间耗尽。

````javascript
function recursive() {
  recursive();  // 无限递归 → 栈溢出（RangeError: Maximum call stack size exceeded）
}
recursive();
````

### 2. 栈存储的是"值"还是"引用"？

* **基本类型**：存的是**值本身**（`name: 'Tom'` 直接存 'Tom'）
* **引用类型**：存的是**堆中的地址（指针）**（`user: 0x001` 存地址）

---

## 🔬 深入理解：堆（Heap）

### 1. 堆的特征（无序、大空间）

````javascript
let obj1 = { a: 1 };
let obj2 = { a: 1 };  // obj1 和 obj2 指向堆中两个不同的对象
console.log(obj1 === obj2);  // false（地址不同）
````

### 2. 垃圾回收（GC）如何回收堆内存？

**引用计数（旧）**：对象被引用时计数+1，引用解除时计数-1，计数为0则回收。

* **缺陷**：循环引用导致计数永不归零 → 内存泄漏

````javascript
let objA = { ref: null };
let objB = { ref: null };
objA.ref = objB;
objB.ref = objA;  // 循环引用 → 引用计数永远为2 → 内存泄漏
````

**标记清除（现代）**：从根对象（全局对象）出发，标记所有可达对象，未标记的则回收。**解决循环引用问题**。

## 🧪 验证代码（跑一遍，观察栈和堆的行为）

````javascript
// ========== 基本类型（栈） ==========
let a = 10;
let b = a;  // b 复制了 a 的值（独立拷贝）
b = 20;
console.log(a);  // 10（a没变）

// ========== 引用类型（堆） ==========
let objA = { count: 10 };
let objB = objA;  // objB 复制了 objA 的地址（指向同一个堆对象）
objB.count = 20;
console.log(objA.count);  // 20（objA也变了）

// ========== 函数调用时的栈帧 ==========
function outer() {
  let x = 1;        // 入栈
  function inner() {
    let y = 2;      // 入栈（栈顶）
    console.log(x); // 通过闭包访问外部变量（链式查找）
  }
  inner();          // inner执行完出栈
  console.log('outer继续');
}
outer();            // outer执行完出栈

// ========== 堆内存泄漏示例 ==========
let leakObj = {};
setInterval(() => {
  leakObj.data = new Array(1000000);  // 不断创建大数组，堆内存持续增长 → 内存泄漏
}, 1000);
````

## 🎯 面试致命追问（附标准答案）

**问：** "JS 中所有数据都存储在堆中吗？"  
**答：** "**不是。** 基本类型（`number`、`string`、`boolean`等）和引用类型的地址（指针）存储在**栈**中，引用类型的实际对象存储在**堆**中。但闭包中的变量可能会被'逃逸'到堆中，因为函数执行完后栈被销毁，但闭包需要保留外部变量。"

**问：** "为什么基本类型存在栈，引用类型存在堆？"  
**答：** "**栈的特点是'小而快'，适合存储固定大小的数据。** 基本类型大小固定（如 `number` 8字节），可以直接在栈中快速访问。**引用类型大小不固定**（对象属性可以动态增加），需要更大的堆空间来存储，栈中只保存指向堆的地址。"

**问：** "闭包中的变量存在栈还是堆？"  
**答：** "**堆。** 正常情况下，函数执行完栈帧被销毁，局部变量也会释放。但闭包使得内部函数持有外部变量的引用，这些变量'逃逸'到堆中，由垃圾回收器管理。"

**问：** "如何判断一个变量存储在栈还是堆？"  
**答：** "看类型：**基本类型 → 栈，引用类型 → 堆**。但有一个例外：`V8` 引擎的'小整数优化'会把小整数直接存为指针，相当于'存在栈'，但这属于引擎实现细节。"

**问：** "栈溢出是什么？如何避免？"  
**答：** "栈溢出是函数调用层数过深（如无限递归），导致栈空间耗尽。**避免方法**：1. 确保递归有终止条件；2. 将递归改为迭代（循环）；3. 使用尾递归优化（但JS不支持）"
