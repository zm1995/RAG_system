这是一个很深入的问题。当叶子节点（数据块）的数量不是2的整数次幂时（比如5个），标准的二叉默克尔树处理方式是：**复制最后一个叶子节点，使其总数补齐到2的幂次**。

我以5个子节点为例，为你图解整个构建过程。

### 初始状态：5个叶子节点

假设有5个数据块：L1, L2, L3, L4, L5。每个叶子节点都是其数据块的哈希值。

````text
节点:  H1    H2    H3    H4    H5
      |     |     |     |     |
数据:  L1    L2    L3    L4    L5
````

### 第一步：补齐叶子节点

二叉默克尔树要求**每个节点都有两个孩子**。为了满足这个条件，当叶子节点是奇数时，常见的做法是**复制最后一个节点**，让它和自己配对。

* 将 `H5` 复制一份，得到 `H5'`。

现在你有了6个叶子节点：`H1, H2, H3, H4, H5, H5'`

### 第二步：构建第一层父节点

将补齐后的6个叶子节点两两配对，计算它们的父节点哈希。

* 父节点 `H12` = `hash(H1 + H2)`
* 父节点 `H34` = `hash(H3 + H4)`
* 父节点 `H55` = `hash(H5 + H5')`  → 注意，这是一个自配对的情况

现在你有3个父节点：`H12, H34, H55`

### 第三步：继续向上构建，再次补齐

3个父节点又是奇数，所以继续采用“复制最后一个节点”的策略。将 `H55` 复制一份，得到 `H55''`。

现在你有4个节点：`H12, H34, H55, H55''`

### 第四步：构建根节点

将这4个节点两两配对，计算出最终根节点。

* 父节点 `H1234` = `hash(H12 + H34)`
* 父节点 `H5555` = `hash(H55 + H55'')`  → 再次自配对

最终，根节点 `Root` = `hash(H1234 + H5555)`

### 完整的默克尔树结构

下面是一个更直观的树形图，其中标记为“副本”的节点就是为了补齐而存在的。

````text
                         Root (最终根哈希)
                        /              \
                 H1234                H5555
                /    \                /   \
             H12      H34          H55     H55'' (H55的副本)
            /  \      /  \         /  \
          H1   H2   H3   H4      H5   H5' (H5的副本)
          |    |    |    |       |    |
         L1   L2   L3   L4      L5   (重复L5)
````

### 这个构建方法的核心要点

1. **复制最后一个节点**：这是处理奇数节点最标准、最通用的方法，比特币和以太坊都采用此方式。关键是，这个“副本”节点指向的是**相同的数据**。
1. **树始终是“平衡”的**：通过复制补齐，最终的树一定是一棵满二叉树，所有叶子节点都在同一深度。
1. **对验证的影响**：
   * **验证原有数据**：流程不变。例如，验证L3时，你依然只需要它的兄弟节点H4和路径上的其他节点（如H12、H5555等）。
   * **验证副本数据**：技术上也可以验证`L5'`，因为它和`L5`是同一个数据块。验证它的路径会和L5稍有不同，但最终会得到同一个根哈希。在工程实践中，通常只验证原始数据，因为副本是为了树形结构完整而存在的，不代表一份独立的新数据。

### 一个更简洁的可选方案：使用平衡树结构

另一种构建方法是不复制节点，而是构建一棵**形状不对称，但高度差不超过1**的平衡树。例如，左子树有4个叶子，右子树有1个叶子，然后右子树再补齐。

````text
         Root
        /    \
     Left    Right
    /    \     |
 H12     H34   H5
 /  \   /  \   |
H1 H2  H3 H4  H5'
````

不过，在实际应用中，**复制最后一个节点**的方案因为实现上更统一简单，所以应用得更为广泛。

这个构建逻辑也解释了为什么在区块链中，一个区块内的交易数量不一定是2的整数次幂，但通过这种方式，总能形成一个唯一的默克尔根。
