了解端插件
什么是端插件
端插件是扣子插件的一种类型，能够使智能体直接与本地设备进行交互，实现对本地设备的控制和信息获取。当大模型推断出需要调用端插件时，会通过消息机制与本地设备建立连接，获取设备的执行结果并返回给大模型继续推理。
用户对本地设备下达指令，指令传递给智能体后，大模型根据端插件的描述判断是否需要调用端插件。若需调用，端插件将直接调用集成的本地设备的能力，实现对设备的控制和信息获取。例如，端插件集成了蓝牙音箱的能力，用户可以通过语音控制蓝牙音箱的音量。
应用场景
直接控制设备
场景：对 Bot 说“播放音乐”，此时手机的音乐响起，Bot 控制了我的手机播放起了音乐！
实现方案：端插件指令为 PlayMusic，客户端实现播放音乐的逻辑，当收到 PlayMusic 指令时，客户端调用手机方法播放音乐。
获取设备信息
场景：对 Bot 说“帮我总结我今天的日程”，此时 Bot 回复：“已获取你手机的日程，并为你总结了相关信息。你的日程是 xxxx”。
实现方案：创建一个端插件，指令为 getCalendarList，客户端实现代码，当收到 getCalendarList 指令时，返回手机日程。提示词中设置“当用户想获取日程时，可以调用 Plugin getCalendarList”。
需要用户 GUI 交互
场景1：
场景：对 Bot 说“可以给我讲个笑话吗”，此时设备上先弹出卡片先让我选择要哪种笑话，我选择了黑色幽默，此时 Bot 开始说（黑色幽默）的笑话”。
实现方案：创建一个端 Plugin，指令为 selectJokesType，客户端实现代码，当收到指令为 selectJokesType 时，弹出卡片让用户选择，用户选择之后，返回选择结果，大模型拿到结果再进行下一轮 ReACT。
场景2：
场景：我对 Bot 说“可以给我播放一首音乐吗”，此时设备弹出汽水音乐授权的卡片，我点击了授权，此时 Bot 开始播起了音乐。
创建一个 Plugin，指令为 playMusic，并勾选需要「端授权」，当 Plugin 运行的时候发现没有权限，就会下发请求授权指令，端上弹起授权卡片，用户授权完之后上行消息，Plugin 恢复状态继续运行。
业务流程
消息 Chat 会有状态机的概念, 触发端插件就会进入 requires_action 状态，Chat 对话不是每次都会进入到 requires_action 更多情况是正常的聊天大模型直接返回了这个对话就会进入到 completed 状态。进入 requires_action 状态则需要通过 submit_tool_outputs 做二阶段提交，来让当前对话重新进入运行态。如果 24 小时内未提交端插件的执行结果，对话转为 expired 状态，需要重新发起对话。

接入流程
1.
创建并绑定端插件。
创建并绑定端插件的详细流程可参考\n创建端插件。然后为智能体绑定端插件。
2.
将智能体发布为 API 服务。
3.
调用 API 使用端插件。
调用发起对话 API 使用端插件。发起对话时，模型会根据用户 Query 自动调用端插件，当对话中触发端插件时，对话状态会流转至 requires_action，开发者需要调用提交执行结果 API，将端插件的执行结果传递给模型，模型会总结这些信息、生成最终回复。
用户收到 required_action 中根据自己事先定义的 name 就可以知道当前自己需要执行的动作，然后执行完成后，再将执行的结果通过请求 submit_tool_outputs 将结论返回。大模型收到用户提交的 submit_tool_outputs 结果后就会继续去执行推理，结合上下文以及端插件执行的结果推理完成后生成回复返回给到用户。
详细说明可参考\n通过 API 使用端插件。
常见问题
端插件和普通扣子插件的区别？
端插件和普通插件都是都是智能体与外界交互的工具。
普通插件调用的是线上服务；端插件调用的是硬件能力。设备方需要先知道自己的设备可以执行具体的指令，然后将对应的指令功能创建为一个端插件，后面大模型智能推理后会判定需要执行某个指令 A，就会将指令给到设备，设备收到指令A后就去具体执行指令A，然后将执行完成的结果返回给到大模型继续去推理。
